Core entities — three-section UML format
User
+Id: int · +Username: string · +Email: string (unique) · +PasswordHash: string · +CreatedAt: DateTime
Navigation: MealLogs · WaterLogs · WaterReminders · CardioLogs · StrengthLogs
MealLog
+Id · +UserId (FK) · +FoodName · +MealType · +Calories · +ProteinG · +CarbsG · +FatG · +ServingG · +LoggedAt
All numeric fields stored in metric units
StrengthLog
+Id · +UserId (FK) · +ExerciseName · +MuscleGroup · +Sets · +Reps · +WeightKg · +Notes · +LoggedAt
Validated: Sets > 0 AND Reps > 0
WaterReminder
+Id · +UserId (FK) · +ReminderTime: TimeOnly · +Label: string · +IsActive: bool
Toggled via PATCH — partial update, not full replace

Functional vs non-functional
Functional — what the system does: log a meal, return a summary, toggle a reminder. If not met, the system does not work.

Non-functional — how well it does it: response time under 500ms, BCrypt password hashing, JWT expiry, parameterised SQL queries.
